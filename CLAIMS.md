# Claims register

One row per claim this repository makes, with the analyses that stand behind
it, the artefact a reader can open, its status in the root vocabulary
(Validated, Descriptive only, Exploratory, Retracted-superseded, Not
established), and a plain judgement of whether the result has potential: a
figure or sentence that carries a hypothesis forward, a lead that needs one more
analysis, or a dead end kept for the record. A claim with no logged artefact
is Not established by definition. Status changes only on the owner's
retain/reject decision (DEVELOPMENT.md); rejected rows stay in the table.
Rows C169 onward, and the dated qualifiers added to earlier rows on
2026-09-29, were proposed under the owner's request to register every claim
and are marked as delegated reassessments until the owner reviews them.

Numbers quoted here come from the artefact named in the row. The stepwise
account of how the analyses relate to each other is
[`Research Article/gate1_01_niethamer_2025/ANALYSIS_TRIAL_PLAN.md`](Research%20Article/gate1_01_niethamer_2025/ANALYSIS_TRIAL_PLAN.md).

Branch 2C (the Choi axis) of the reading order since 2026-09-15; see
[`Research Article/README.md`](Research%20Article/README.md). The trial gates named in this
section (0, 1, 2a, 2b, 2d) are the owner's analysis gates for this paper,

paper pools three mice and each genotype contributes one library per sort, so

## How to keep this register honest

- Add a row only when a run record or decisions log exists for it.
- After changing a row's status, re-run `analysis/scripts/14_write_negative_results.py`;
  [`NEGATIVE_RESULTS.md`](NEGATIVE_RESULTS.md) is generated from this file and is
