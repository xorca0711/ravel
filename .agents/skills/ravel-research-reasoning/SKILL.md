# Ravel research reasoning

Use the current checkout's AGENTS.md and research governance as authority. This
skill applies their decision workflow; it does not create claim acceptance,
authorize external actions or require a new experiment. Repository-relative paths
below resolve from the Git root, even when the session starts in a subdirectory.

## Establish the decision

Read AI_CONTEXT.md, PROGRESS.md and docs/RESEARCH_GOVERNANCE.md. Use
analysis/research/registry.json to locate the owner's current result, amendment,
question guide and dossier. Read current evidence before historical plans.
Confirm scope with the user's actual request; never choose an RQ merely because
it is the most recently updated one.

For substantive work, briefly connect the organizing biological purpose, the
current hypothesis or estimand, and the executable comparison. In the existing
owning record, explain: published premise -> repository observation -> unresolved
question -> informative comparison -> what its outcomes would change. State the
unit, endpoint, exposure and consequential alternative or validity threat. These
items can be prose; do not add a mandatory checklist file or fill unknowns with
invented values.

Follow docs/governance/AGENT_DECISION_WORKFLOW.md for work-type routing.
Description, faithful replication and mutant/control effect questions can be
worthwhile without a new mechanism, rescue arm or full causal chain. Reuse
sufficient evidence; an available method or plugin alone does not justify work.
Select a specialist skill only for a concrete literature, biological or
implementation need, after checking its availability and scope.

## Preserve useful distinctions

- Population abundance, spatial arrangement and within-state differences can
  each be meaningful and can coexist. Determine which the question actually
  owns. Composition evidence does not automatically establish a beyond-mixture
  increment, but it is not automatically nuisance.
- Describe RNA, morphology, inferred lineage and functional output as their
  measured endpoints. A missing later endpoint limits that claim; it does not
  erase informative upstream work or refute the original biological premise.
- Treat a failed source route as a bounded access finding. Hold only steps
  requiring the exact missing inputs; retain useful qualified work.
- Shared samples or source datasets remain shared-source evidence. A later freeze
  does not erase exposure. Retain negative and mixed results and existing RQ IDs.
- Follow docs/governance/LITERATURE_WORKFLOW.md when materially developing a
  question. Reuse valid prior reading and distinguish published findings from
  repository observations and proposed explanations.

New numerical work uses the existing contract/preflight/runner. This skill
does not loosen eligibility or change historical outputs. Metadata recovery and
exploration retain their own permitted scope.

## Interpret and deliver

After a substantive step, state what narrowed, weakened, stayed mixed or remained
unestimated, and why the next decision follows. If there is no informative next
step, say so. Revise the current README/context/dossier as appropriate, rather
than stacking completion notices ahead of the argument; retain historical and
hash-bound records. Explain when a current interpretation remains valid.

Review the changed reasoning for purpose drift, blanket source holds, discarded
population explanations, RNA-to-function leaps and missing unfavorable results.
Execution completion and biological resolution are separate. Use required
repository checks and update PROGRESS.md; a hook, validator or AI review supplies
no human scientific acceptance.
